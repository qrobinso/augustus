# Breakout podcasts

A breakout is a separate, on-demand episode about one subject. Users launch it from a visible dashboard action or from the player with the current chapter preselected. A shared dialog offers a saved topic, a typed subject, or a chapter of the source briefing; optional focus; 5/10/20 minute targets (API accepts 3–30, default 10); and cast selection. Existing audio keeps playing. On acceptance show the queued result with a detail link; never autoplay or replace the source.

Reuse Briefing storage, queue, progress, cancellation, TTS, playback and transcript. Persist extra_data.kind='breakout' plus breakout metadata before scheduling so queued jobs survive restarts. API POST /api/briefings/breakout accepts exactly one target: topic, topic_id, or source_briefing_id with chapter_index. Optional focus, max_duration_minutes, cast_id. Return normal BriefingResponse with HTTP202. Profile/user ownership enforced for topic, source and cast. Inherit source cast when none selected. Snapshot chapter context server-side; do not accept arbitrary parent transcript from clients. A breakout from a chapter links to its source and can still be generated if the original later changes or is deleted.

The pipeline performs focused multi-angle web research (background/mechanism, evidence/examples, competing views, implications) and produces one coherent deep-dive narrative. It bypasses daily novelty filtering and duration shortening, since revisiting a topic is explicit intent. Sources come from actual retrieved pages; insufficient research produces a useful failure, not invented supporting material. Do not turn research sections into new story-memory events or mark the parent heard. Reuse both LLM providers and selected TTS. Respect timeout/cancellation.

MCP exposes generate_breakout_podcast with the same request shape, standard result links and async polling guidance. Tool catalog, key allowlists and audit behavior stay aligned. Existing API-key identity path is currently missing in get_current_user despite MCP relying on it; restore valid/revoked-key handling and bound-profile resolution so MCP actually works. New breakout endpoint enforces generate_breakout_podcast permission for API keys; normal local UI remains supported.

No new playback engine, external publishing, scheduling UI, or automatic generation. Prior story-memory/Codex work stays intact and uncommitted.
